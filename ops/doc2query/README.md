# doc2query: generated questions added to the chunk index

Production rollout of variant C of the chunk track (measured in the chunk lab, `ops/eval/chunk/`): for every chunk of the pages of 3 chunks or more, 3 to 5 questions generated by Claude Haiku are added

1. to the chunk's **embedding text**, inside the native context block: `<context>{title}\n{questions}\n</context>\n{chunk}` (not cut at 300 characters, unlike synopses);
2. to the chunk's **keyword vector** (`search_vector`), at weight C, the chunk itself staying at weight B.

`content_chunks.chunk_text` is never modified: excerpts, Jev and display read the original chunk. Code blocks (`fenced_code`) and images are never enriched.

"gbrain indexes, Claude reasons": gbrain calls no chat model. It stores the questions, indexes them and reports what is missing; generation happens through `claude -p`, outside gbrain.

## How it works

- **Storage**: table `chunk_index_text` (migration v265): `source_id`, `slug`, `chunk_hash` (sha256 of the chunk text), `kind` (`d2q`), `text`, `model`, `prompt_version`, `created_at`; unique key (`source_id`, `slug`, `chunk_hash`, `kind`). A chunk whose text changes has no questions any more (different hash) until the next generation. This is derived database data: no page write, no revision, nothing in the content repository, no trip through the managed mode's page coordinator.
- **Setting**: database config key `search.chunk_index_text`, value `d2q`; absent (the default) = off. A database key rather than an environment variable, so that the launchd sync, the server, the nightly cycle and the CLI all see the same value: otherwise a process without the variable would re-embed pages without the questions.
- **Setting off**: nothing reads the table. Embedding texts, input hashes (`embedding_input_hash`) and keyword vectors are byte-identical to those of a brain without the feature (checked by the tests).
- **Setting on**: every embedding path adds the questions (import and sync, `embed <slug>`, `--all`, `--stale`, backfill, the managed mode's embedding worker, the context service, segmented pages), and the vector's input hash covers them: a vector built without them reads as stale, and the reverse. `embed --stale` keeps them. The keyword vector is computed by the `update_chunk_search_vector` trigger, which reads the questions through `gbrain_chunk_index_text()`.

## Commands (on the brain host only)

```bash
gbrain chunk-text status                          # setting, number of texts and pages
gbrain chunk-text pending [--min-chunks 3] [--limit-pages N] [--json]
gbrain chunk-text import <file.jsonl>             # stores, then refreshes the touched pages (when on)
gbrain chunk-text refresh [--slug S]              # re-embeds what needs it, recomputes keyword vectors
gbrain chunk-text prune [--all]                   # deletes orphaned texts (--all: every one)
```

One line of the import JSONL: `{"source_id": "default", "slug": "...", "chunk_hash": "<sha256>" | "chunk_text": "...", "chunk_index": 3, "questions": ["...", "..."], "model": "claude-haiku-5-5", "prompt_version": "3-questions"}`. A line whose hash matches no current chunk of the page is ignored and counted.

## Turning it on

```bash
gbrain config set search.chunk_index_text d2q
gbrain chunk-text refresh            # aligns vectors and keyword vectors of the pages that already have questions
```

Initial build: either let the nightly job catch up in slices of 40 calls (548 calls for the whole index, so about 14 nights), or run `python3 -I ops/doc2query/generate.py --max-calls 600` once (about 80 minutes at 6 in parallel, measured in the lab). Questions already generated in the lab on 2026-10-21 can also be reused without any call: `python3 -I ops/doc2query/convert-lab-cache.py --out <file>` then `gbrain chunk-text import <file>` (chunks changed since are ignored).

## Nightly generation

`ops/gbrain-nightly.sh`, step 2d, after the dream and the hygiene: when the setting is `d2q`, `ops/doc2query/generate.py --max-calls 40`

1. reads `gbrain chunk-text pending --json`;
2. calls `claude -p --model claude-haiku-5-5`, one call per page (groups of at most 14 chunks; past 45,000 characters, the start of the page plus the group's chunks, 8 at a time), hooks off, no MCP server, no tool, the lab's v3 prompt reduced to the questions, and a deterministic filter on questions about what the passage does not contain;
3. writes `~/.gbrain/doc2query/d2q-<date>.jsonl` (and the call log `.calls.jsonl`);
4. calls `gbrain chunk-text import`, which re-embeds and recomputes the keyword vectors of the touched chunks only.

Options: `--max-calls` (default 40, protects the quota), `--jobs` (4), `--dry-run` (plan without calls), `--no-import`, `--gbrain "<command>"` (for instance the lab).

### Prompt

The built-in prompt is a neutral English one that asks for the questions in the language of the page. To use your own, point `DOC2QUERY_PROMPT_FILE` (user prompt) and `DOC2QUERY_SYSTEM_PROMPT_FILE` (system prompt) at template files. A file is read verbatim, one trailing newline dropped; the user prompt is filled with `str.format` and the placeholders `{title}`, `{slug}`, `{type}`, `{doc}` and `{targets}`, so literal braces are doubled (`{{ }}`). The deterministic filter matches French phrasings only (the language the lab measured).

## Turning it off and rolling back

```bash
gbrain config unset search.chunk_index_text
gbrain chunk-text refresh            # re-embeds without the questions the chunks that had them, recomputes their keyword vectors
```

The questions stay in the table (no effect with the setting off): it can be turned back on without regenerating. To delete them: `gbrain chunk-text prune --all`. Reverting the migration is not needed: the table and the function are inert with the setting off.

## Known limits

- A segmented page (body stored in segments) gets the questions in its keyword vector and at its next embedding, but `chunk-text refresh` does not re-embed its existing vectors.
- The cost estimate of an embedding model migration (`embedding-migration-worst-case.ts`) does not count the questions of stale chunks (about 330 characters per enriched chunk).
- Jev does not see the questions: it receives the title and the original chunk.
